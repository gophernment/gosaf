# GoSaf v0.2 — Prove It, Make It Operable

Date: 2026-10-14
Status: draft, awaiting review
Builds on: `2026-10-14-gosaf-core-design.md` (v0.1). Roadmap: `ROADMAP.md`.

## 1. Goal

Make GoSaf provably correct and measurably no slower than `sony/gobreaker`, and give
operators the controls they need during an incident. Release gate (decided by the owner):
**GoSaf must not be slower and must not allocate more than gobreaker on the hot paths
before v0.2.0 is tagged.**

## 2. Baseline (measured 2026-10-14, macOS arm64, Go 1.27.2, gobreaker v2.4.0)

| Benchmark (serial) | GoSaf v0.1.1 | gobreaker | Spike result (throwaway) |
|---|---|---|---|
| Closed, success | ~88 ns, 48 B, 1 alloc | ~79 ns, 0 B, 0 alloc | median 70.4 ns, 0 alloc |
| Open, reject | ~43 ns, 16 B, 1 alloc | ~37 ns, 0 B, 0 alloc | median 37.9 ns, 0 alloc |

Profile of v0.1.1: about 64% of the time is `time.Now()` (it reads both wall and monotonic
clocks, twice per call). A `Permit` (48 B) and a `RejectedError` (16 B) are allocated per call.
The spike removed all three costs and reached the gate. Parallel runs are lock-bound and equal.

## 3. Scope

In:
- **A. Performance** — zero-alloc hot paths; cheaper default clock.
- **B. Evidence** — benchmarks vs gobreaker, model-based tests, machine fuzzing, `synctest` test.
- **C. Operations** — `ForceOpen`, `Disable`, reject events, richer `Snapshot`, `slog` listener.
- **D. Supply chain** — signed tags, release workflow, Scorecard, release checklist.

Out: adapters (v0.3), recovery policies (v0.3), shared state (v0.4), `ForceClose`
(`Reset` already closes and clears; a second name adds nothing).

## 4. A. Performance design

1. **Ticket path.** `guard` gains `Begin(ctx) (Ticket, error)` and `End(Ticket, error)` where
   `Ticket{gen uint64; start time.Time}` is a plain value. `gosaf.Do` uses them, so the common
   path allocates nothing. `Allow` becomes `Begin` plus a heap `*Permit` that wraps a `Ticket`
   and adds the idempotent `Done` (atomic flag). Behavior of `Allow`/`Done` is unchanged.
2. **Shared rejection errors.** `circuit.Admission` carries `RetryAt time.Time` instead of
   `RetryAfter`. The guard keeps the last `*RejectedError` and returns it again while
   `(state, RetryAt)` is unchanged (checked under the existing lock). A new error is allocated
   only when the Open period or probe deadline changes.
3. **Immutable errors.** Because the error is shared, `RejectedError` fields become unexported
   and exposed through methods, so a caller cannot change what other callers see:
   `State() State`, `RetryAt() time.Time`, `RetryAfter() time.Duration` (`max(time.Until(RetryAt), 0)`,
   documented as using the wall clock, not `Config.Clock`). **Breaking** relative to v0.1
   (fields to methods); allowed in 0.x and listed in the changelog.
4. **Default clock.** When `Config.Clock` is nil, the guard uses
   `origin.Add(time.Since(origin))` (one monotonic read) instead of `time.Now()`. Events that
   need wall time (`StateChange.At`) take `time.Now()` at emission, which only happens on
   transitions. A custom `Config.Clock` is used as before for everything.

5. **Lock-free reject window** (added during planning after the gate failed on the reject path:
   median 38.2 ns vs gobreaker 36.5 ns, 69% of it spent reading the clock). While the machine is
   Open in normal mode (or forced open), every call is rejected identically and changes no state.
   `circuit.Machine.RejectWindow()` describes that period; the guard publishes an immutable copy
   (`from`, `until`, shared error) through an `atomic.Pointer` whenever the machine's state,
   mode or window changes (under the existing lock). `Begin` first checks the pointer and, if the
   clock is inside `[from, until)`, rejects without taking the lock (the rejected counter is an
   atomic). Outside the window, or on any other state, it takes the normal locked path. The
   window is cleared on every transition out of Open, on `Reset` and on mode changes, and it is
   re-published when a clock step back restarts the Open wait. Measured on the prototype: reject
   29 ns vs 37 ns serial and 61 ns vs 146 ns parallel.

Invariants kept: domain package has no clock access; no lock held across user code;
non-monotonic clocks cannot stick Open or Half-Open (v0.1.1 tests stay).

## 5. B. Evidence design

- **`bench/` module** (own `go.mod`, requires gobreaker v2.4.0, `replace` to the parent).
  Benchmarks: Closed success, Closed failure, Open reject; serial and parallel; `ReportAllocs`.
  `bench/gate.sh` runs each 10 times, takes medians, and fails if GoSaf's ns/op is more than
  2% above gobreaker's or its allocs/op is higher, on Closed-success and Open-reject (serial).
  Run before every release (documented in `RELEASING.md`). CI runs the benchmarks in a
  non-blocking job and prints the table, because shared runners are too noisy to gate on.
- **Oracle and invariant tests** (`internal/circuit/model_test.go`). A single full duplicate of
  `Machine` would only restate the same code, so the tests use independent oracles per rule:
  naive windows (slices, linear scans) compared with the real count and time windows over random
  operations including clock steps back; an exact-arithmetic oracle for the Closed trip rule
  (`MinCalls`, failure rate, slow rate, consecutive failures); and a naive oracle for the
  Half-Open decision (re-open as soon as the best case is unhealthy, close when all probes
  succeed). Seeded random operation sequences (`Admit / Record / advance / step back / Reset /
  ForceOpen / Disable`) check invariants after every step: transitions form a chain from the
  previous state to the current one, `RetryAt` stays in range, counts are consistent and bounded,
  a disabled machine admits everything, and (liveness) unless forced open the machine admits a
  call again within three timeout periods, so it can never be stuck.
- **`FuzzMachine`**: native fuzzing decodes bytes into the same operations and runs the same
  invariant checks.
- Each test was checked by mutation: deliberately breaking the code makes it fail.
- **`synctest` test** (`gosaf` package): one end-to-end test with the default clock inside a
  `testing/synctest` bubble: a hung probe re-opens the circuit after `ProbeTimeout`; a time
  window expires old failures. No fake-clock plumbing needed.
- Existing tests stay; new behavior is test-first.

## 6. C. Operations design

**Modes** (domain, in `Machine`): `Normal`, `ForcedOpen`, `Disabled`.
- `ForceOpen()` — state becomes Open and stays Open: no automatic Half-Open, every call
  rejected with `ErrOpen` whose `RetryAt` is the zero time (`RetryAfter()` returns 0, meaning
  "no scheduled retry"). Emits a normal `StateChange` (Closed/HalfOpen to Open).
- `Disable()` — bypass: every call is admitted, nothing is recorded, state is unchanged.
  Escape hatch if the breaker itself is the problem.
- `Reset()` — returns to `Normal` and `Closed` with an empty window (existing behavior plus mode).
- Mode changes bump the generation, so in-flight results are dropped as with `Reset`.
- `Snapshot.Mode` shows the current mode. No automatic expiry: forced modes are explicit and
  must be cleared by `Reset()`.

**Reject events.** New optional interface (kept optional so existing `Listener` implementations
keep compiling):

```go
type RejectListener interface { OnReject(RejectEvent) } // RejectEvent{Name string; State State}
```

The guard checks once in `New` whether the configured `Listener` also implements it; if not,
the reject path pays nothing. Called after unlock, panic-contained like other callbacks.

**Snapshot additions**: `Mode`, `Rejected uint64` (rejections since creation, incremented under
the existing lock), `LastChange time.Time` (zero if no transition yet).

**`slog` listener**: new package `gosafslog` (stdlib only, same module):
`gosafslog.NewListener(*slog.Logger) gosaf.Listener`. Logs state changes (Warn on Open, Info
otherwise), rejections and calls at Debug. Never logs error text or payloads.

## 7. D. Supply chain design

- **Signed tags**: tags are created with `git tag -s` (owner's GPG key). `RELEASING.md`
  documents the checklist: changelog entry, `bench/gate.sh` pass, full checks, signed tag,
  `git tag -v`, push.
- **Release workflow** (`.github/workflows/release.yml`, on `v*` tags): re-run the full check
  suite, then create a GitHub Release from the matching `CHANGELOG.md` section using the
  preinstalled `gh` CLI (no third-party action). Fails if the changelog section is missing.
  Permissions: `contents: write` for that job only.
- **OpenSSF Scorecard** workflow (weekly + on push to main), action pinned by SHA, results
  uploaded as SARIF. Informational, not blocking.
- Existing: Dependabot, pinned actions, `govulncheck`, `staticcheck`.
- Not doing in v0.2: SLSA provenance attestation. A pure Go library has no build artifact; the
  Go checksum database already protects module contents. Revisit if binaries are ever shipped.

## 8. Architecture placement

- `internal/circuit`: `Mode`, mode handling in `Machine`, `Admission.RetryAt`. No new imports.
- `internal/guard`: `Ticket`, `Begin/End`, shared rejection cache, `RejectListener`, counters,
  clock selection. Imports `circuit` only.
- Root `gosaf`: re-exports, `Breaker.ForceOpen/Disable`, `Do` on `Begin/End`.
- `gosafslog/`: depends on root `gosaf` only.
- `bench/`: separate module; the only place gobreaker appears. The root `go.mod` stays
  dependency-free.

## 9. Compatibility

Breaking relative to v0.1.x (allowed in 0.x, recorded in `CHANGELOG.md`): `RejectedError`
exported fields replaced by methods. Everything else is additive. Semantics of existing
methods are unchanged.

## 10. Secure coding notes

- Shared error values are immutable (unexported fields).
- Forced/disabled modes are explicit; no hidden auto-expiry. `Disable` is documented as
  removing protection.
- Counters (`Rejected`) are `uint64`; no signed overflow. Rejection cache holds one pointer.
- Callbacks (`OnReject`) run outside the lock and are panic-contained.
- The release workflow has least-privilege permissions and no secrets.

## 11. Acceptance

1. `bench/gate.sh` passes (median ns/op within +2% and allocs/op not higher than gobreaker on
   Closed-success and Open-reject; the spike already beat both).
2. Model-based and fuzz tests agree with `Machine`; no sequence leaves it stuck.
3. All checks green in CI on Linux; coverage of `circuit` and `guard` does not drop.
4. `ForceOpen` / `Disable` / `Reset` / `OnReject` / `Snapshot` additions have tests written first.
5. `RELEASING.md`, release workflow and Scorecard workflow exist; the v0.2.0 tag is signed.
